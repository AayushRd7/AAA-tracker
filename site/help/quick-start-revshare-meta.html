Rev-share offer with Meta traffic, end to end

Wire a rev-share offer to Meta traffic end to end: campaign link, postback, click id stitching and the conversion API.

Updated 5 October 2026

What “rev-share with Meta” changes

Two things make this setup different from a fixed-payout offer. A rev-share offer pays you a share of the sale value, and that share is almost never known when you paste the offer URL — it arrives with each conversion, on the postback. And with Meta you are buying the clicks yourself, so the click id has to survive from the ad click, through the network, and back to the tracker. This page wires both ends together.

The rev-share consequence is simple: set the offer payout to 0. The real amount comes back in the postback’s payout (or amount/sum) field and accumulates on the conversion. If you leave a fixed payout on the offer you will over-report revenue before the network’s number lands.

Step 1 — Add the affiliate network

Open Manage → Networks → Add network, or start from the preset catalog (125 networks) so the record is pre-filled. A network stores the two things this walkthrough depends on: its own click-id convention (the parameter it will echo back, for example s1={click_id} or aff_sub={click_id}) and its S2S postback template. If you add it by hand, type both in exactly as the network documents them.

Step 2 — Hand the network the postback URL

Open the network record’s S2S postback template and copy the URL into the network’s own conversion-tracking panel. The endpoint is:

https://YOUR-TRACKER-DOMAIN/pb?clickid={clickid}&payout={payout}&status={status}&tid={tid}

The preset template uses generic placeholders. The network’s panel fills macros of its own naming, so swap any placeholder the network names differently for that network’s token before you save. A payout macro called {sum} and a transaction macro called {txn} give a URL like:

https://YOUR-TRACKER-DOMAIN/pb?clickid={clickid}&payout={sum}&status={status}&tid={txn}

The parameter names on the left stay the tracker’s — or an accepted alias, since sum on its own is read as the payout name. Only the value macro changes to match what the network can fill. The full list of accepted names and what a good response looks like is on the postback reference; to lock the endpoint down with a secret key and an IP allowlist, see Securing your postback URL.

Step 3 — Add the offer with the network’s click-id parameter

Open Manage → Offers → Add offer. Set the Target URL to the network’s offer URL and insert the network’s own click-id parameter with the {click_id} macro. If the network expects sub1, that is:

https://network.example.com/click?offer=123&sub1={click_id}

The tracker already appends click_id=… to the offer URL automatically, but a network reads its own parameter, so you add that parameter yourself. The network record’s “Offer parameters” field is only a stored reference — it is not appended at runtime — so never rely on it to get the id onto the URL. Set Payout to 0, pick the currency the network pays in, and leave the offer Active. The offers page details every field.

Step 4 — Add the Meta traffic source

Open Manage → Traffic sources → New from template and pick Meta. The preset captures fbclid from the ad URL automatically and stitches it with the _fbc and _fbp cookies — you do not map it. See Adding a traffic source if you would rather build it by hand.

Step 5 — Create the campaign and copy the link

Open Manage → Campaigns → Create campaign. Give it the Meta source and the offer, and run through the wizard. On the Settings step, set Ad-platform campaign ID to the Meta campaign’s id so spend can be matched later. Save, then copy the Campaign URL:

https://<your-domain>/<alias>

The link accepts click_id, cost, sub_id_1…sub_id_10, utm_* and external_id, so your Meta ad URL can carry the cost and any labels you want back. The wizard itself is covered in Campaigns and flows.

Step 6 — Connect Meta CAPI and cost sync

Two separate connections, both under Manage:

  • CAPI — Manage → CAPI integrations, switch on Send conversions to Meta, then set the Dataset/Pixel ID and access token, a default currency and the statuses to send. Leave dry-run on to build and log the payload without sending, use Send test event to confirm the wiring, then turn dry-run off. Full detail: Sending conversions to Meta (CAPI).
  • Cost sync — Manage → Integrations, connect Meta. Spend is matched to a campaign by its Ad-platform campaign ID from Step 5. See Syncing Meta ad spend.

Step 7 — Test it end to end

There is no test-click or test-postback button. The honest test is the real path:

  1. Open the campaign link in a browser, optionally with ?cost=1.25.
  2. Open Logs → Clicks, find the newest row and copy its click id.
  3. Send the postback by hand, exactly as the network will:
curl "https://YOUR-TRACKER-DOMAIN/pb?clickid=YOUR-CLICK-ID&payout=12.50&status=sale"

A {"status":"ok",…} body confirms the endpoint. Then open Logs → S2S postbacks for the inbound call, Reports → Conversions for the recorded sale, and Health centre to see the last successful postback. If nothing lands, Postback not recorded splits the 400, 403 and no-match cases.

The two mistakes that cost the most

First, leaving a fixed payout on the offer: with rev-share the payout must be 0, because the money is whatever the postback says. Second, forgetting the network’s own click-id parameter on the Target URL — the auto-appended click_id=… is not the name the network reads, so the postback comes back with nothing to match.
