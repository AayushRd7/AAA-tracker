How cost reaches a report

Cost can arrive from three places, and a wrong number is usually a mismatch between them. Per-click cost comes from the cost parameter on the campaign link, or from the campaign's configured cost; synced spend comes from an ad platform; and a manual correction can be applied retroactively in Reports. Work the checks in order to find which of these is missing or feeding the wrong value.

1. Is there an Ad-platform campaign ID on the campaign?

Cost sync matches a platform's spend to your campaign by id first. Open Manage → Campaigns, edit the campaign, and set Ad-platform campaign ID — for Meta this is the Meta Ads campaign id. Without it the sync falls back to matching by campaign name, then by the campaign's configured tracking identifiers; if none match, the platform's spend for that campaign is never attached and the campaign shows no synced cost.

If Meta is connected, the field offers discovered campaigns to pick from, so copy the id from there rather than typing it.

2. Is Meta connected, and is the ad account selected?

Cost sync has two switches outside the campaign. Open Manage → Integrations and check the Meta tile shows connected. Then, in the Ad accounts for cost sync picker on that tile, choose the ad accounts whose spend you want read, and press Save accounts. A connected platform with no account selected syncs nothing.

If the tile reads Needs reconnect, the stored token can no longer be read or has expired — reconnect before looking at anything else.

3. Has the backfill window reached the day?

The sync does not walk your whole history. It queries a rolling window ending today, going back a fixed number of days — by default 7. A day older than that window is never re-fetched, so its spend stays at whatever was last written, or at zero if the campaign was created after the day passed.

The tell is a cost that is correct for recent days and missing for older ones. Wait for the next scheduled run (the sync runs on a cadence, hourly or daily) and confirm the day is inside the window; if you need older days, widen the backfill window and re-run.

4. Currency mismatch

This is the check people skip, and it makes a correct-looking cost read wrong. Spend is stored in the currency the ad platform reports for that ad account. Three currencies can be in play:

  • the ad account's currency, which is what the platform returns;
  • the campaign's Cost currency field (Manage → Campaigns);
  • the workspace base currency from Settings → Multi-currency, which reports convert to before aggregating.

If the campaign's Cost currency does not match the currency of the spend you are comparing it to, the figures will not line up. Multi-currency converts revenue, cost and payout into the single base currency, so once set, check that the ad account and base currency are on the same page. There is no currency parameter on /pb — a postback never sets currency; it comes from the offer or workspace.

5. Manual campaign cost versus synced spend

Two mechanisms can both write per-click cost, and the last writer wins per campaign and day:

SourceWhen it appliesBehaviour
cost parameter on the campaign linkCampaign has Cost from cost parameter on; the source maps its token to cost.Stored on the individual click; falls back to the campaign's Cost value for the whole period otherwise.
Synced platform spendCampaign matched by Ad-platform campaign ID.Authoritative for that campaign and day; re-running a day replaces it (never adds), so re-syncs are idempotent.

The campaign's Cost model (CPC, CPUC, CPM, CPA, CPS, RevShare, Auto) and its Cost value define the manual fallback. If a campaign has a stale manual cost, the sync overwrites it for any day it matches — so check whether the number you are seeing predates the last sync run.

6. The retroactive cost update in Reports

For a correction the sync cannot make — an unmapped campaign or a one-off fix — open Performance → Reports and use the Cost update action. The Retroactive cost update dialog sets per-click cost on every matching analytics row:

  1. Choose a Campaign, or leave it empty to apply to all campaigns.
  2. Set the From and To dates for the window.
  3. Enter Cost per click and press Apply.

Total spend becomes cost × matched rows, and existing costs are overwritten, not adjusted. Enter 0 to clear cost from a window. Each run is recorded in Logs → Cost updates with the user, campaign, date range, cost and number of rows changed.

Correcting one day does not stick if the sync still covers it

The last writer wins per campaign and day. A manual retroactive update is overwritten the next time the platform sync covers that same day. Fix the mapping or the campaign id first, or the manual correction will be replaced.

Confirm where a number came from

Logs → Cost updates shows manual edits. To see a per-click value actually recorded on traffic, check Logs → Clicks. Comparing the two tells you quickly whether the figure you are disputing came from a manual update or from the sync.
