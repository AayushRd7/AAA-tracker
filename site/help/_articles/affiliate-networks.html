What an affiliate network is

An affiliate network is the party that pays you for a conversion. It groups your offers, stores the click-id convention the network expects, and holds the postback template the network will call. An offer points at a network; a campaign does not, so the same network record can sit behind many offers.

The catalog and "From catalog"

Open Manage → Networks. The catalog ships around 125 presets, each with the network's click-id parameter and its standard postback template pre-filled. From catalog opens it; Add affiliate network opens a blank form.

In the catalog you can search by network name or vertical, and narrow by vertical chips (Dating, Gambling, Nutra, Sweepstakes, and others). Once added, a preset network is marked as a Preset and can still be edited like any other. The catalog can also be opened from the offer editor: the Affiliate network picker has a + button that creates a network without leaving the offer form.

Offer parameters is a stored reference

This is the field readers get wrong. Offer parameters is not appended to your offer URL at runtime. It is a note-to-self: it records what the network calls your click-id parameter, so you know what to write when you build the offer's Target URL.

The tracker already appends click_id=… to every offer URL automatically, but a network almost always reads the id under its own name. You add that yourself in the offer's Target URL. If the network's Offer parameters say s1={click_id}, then the offer URL gets:

https://network.example.com/offer?aff=12345&s1={click_id}

At click-out, {click_id} is replaced with the tracker-generated id, and the network echoes it back on the postback. Repeat that for any extra fields the network wants, such as &s2={sub_id_1}. The full macro list and the click-id round trip are covered in Offers and offer URLs and Click IDs and URL macros.

The click id must be in the offer's Target URL

Writing s1={click_id} into Offer parameters does nothing by itself. If you never place &s1={click_id} in the offer's Target URL, the network never receives your click id — the click still records, but the conversion comes back with nothing to match it to. See Postback not recorded.

The S2S postback URL is the template you hand over

On a network, the S2S postback URL is inbound: it is a URL on your tracker that the network calls when a conversion happens. The preset fills it with the standard template:

https://YOUR-TRACKER-DOMAIN/pb?clickid={clickid}&payout={payout}&status={status}&tid={tid}

Replace YOUR-TRACKER-DOMAIN with your tracker domain and paste the result into the network's own conversion-tracking settings. The braces are the network's macros — it substitutes its real click id and payout when it calls you. This is the opposite direction from a traffic source's postback URL, which is outbound. The accepted parameters, aliases, defaults and responses are all in the postback reference.

Same URL, network's own macro names

The template above uses {clickid}, {payout}, {status} and {tid} because those are common network macro names. The tracker accepts those aliases case-insensitively, so you rarely need to change the template — just paste it where the network asks for its postback URL.

Confirming it works

  • Logs → S2S postbacks shows inbound calls from the network as they arrive, including any rejection and its reason.
  • Reports → Conversions is where a recorded conversion can be inspected, edited or deleted.
  • Health centre shows whether postbacks are landing, which is the quickest signal that the network has gone quiet.
