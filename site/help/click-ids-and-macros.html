Click IDs and URL macros

How click ids travel from the campaign link to the network and back, and the macros you can drop into an offer URL.

Updated 5 October 2026

What a click id is

Every click the tracker records gets a click id — a unique value generated at the moment of the click. It is the thread that ties a click to the conversion that arrives later: the offer URL carries it out, the network echoes it back on the postback, and the tracker joins the two. Get the click id round the loop intact and attribution is exact; lose it and the tracker has to fall back to a less certain match.

The click-id lifecycle

  1. Generated at the click. When a visitor hits the campaign link https://<your-domain>/<alias>, the tracker generates a click id — unless the link already carried one in click_id, in which case that value wins and is kept.
  2. Passed to the offer. At click-out the tracker substitutes {click_id} in the offer URL wherever it appears, and always appends click_id=… to the final URL.
  3. Handed to the network in its own parameter. Most networks ignore click_id and read a name of their own choosing, so you add it to the offer's Target URL — for example &sub1={click_id} or &aff_sub={click_id}.
  4. Returned on the postback. The network calls /pb with the value in a click-id alias such as clickid, subid or cid, and the tracker matches it back to the click.

The offer-parameters field is a stored reference

An affiliate network record has an Offer parameters field that stores that network's click-id convention (for example s1={click_id}). It is documentation you keep next to the network — it is not appended to your offers at runtime. The macro has to live in the offer's own Target URL for the network to receive it.

See Offers and offer URLs and Adding an affiliate network for where each piece is entered.

The sub-id chain

sub_id_1 through sub_id_10 are ten free slots for values your traffic source passes on the campaign link — ad set, creative, keyword, placement, anything. The tracker stores them on the click and exposes them as offer macros, so you can forward the ones the network should see (for example &s2={sub_id_2}), and the network can echo them back on the postback as passthrough fields. That chain is what lets a report split revenue by the source's own granularity, and it is the fallback key when a clickless conversion has no transaction id.

What the campaign link accepts

ParameterPurpose
click_idThe source's own click id; kept instead of generating a new one.
costPer-click cost for this hit.
sub_id_1 … sub_id_10Your own identifiers, carried end to end.
utm_source, utm_medium, utm_campaignCampaign tagging; other utm_* values are collected too.
external_idThe source's own entity id (ad, ad set).
country, region, city, genderExtra attributes some sources append.

Anything the source does not send is simply left empty. If a source uses different names, map its token to the canonical one in that source's paramsIdMapping (for example clickid → click) — see Adding a traffic source.

Offer URL macros

Place a macro in single braces anywhere in the offer URL; the tracker replaces it with the value from the current hit. Unknown macros are left exactly as written, so a typo shows up in the URL rather than silently blanking it.

MacroValue
{click_id}The click's unique id
{sub_id_1} … {sub_id_10}Sub-ids 1–10
{external_id}External (ad) id
{visitor_id}First-party visitor id, stable across sessions
{country} {region} {city}Geo
{ip} {isp} {connection_type}Network and connection
{os} {os_version}Operating system
{browser} {browser_version}Browser
{device_type} {device_brand} {device_model}Device
{language}Visitor locale
{referrer} {keyword}Referrer and search keyword
{cost} {currency}Click cost and its currency
{utm_source} {utm_medium} {utm_campaign} {utm_creative}UTM tags carried by the hit
{offer_id} {campaign_id} {landing_id}Tracker object ids
{payout}The offer's payout
{_md5}MD5 hex of the click id

{_md5}

{_md5} is the MD5 hex digest of the click id — a fixed-length, opaque version of the same value. Use it when a network wants a hashed or length-limited identifier, or when you want a deterministic token that cannot be traced back to the raw id. The same click id always produces the same {_md5}, so it works as a stable join key on the network's side too.

Lander and fallback macros

Inside a local lander's HTML, the placeholder {offer} is replaced with the click-out URL /c/{alias}/{offer_id}, so a button like <a href="{offer}">Continue</a> always routes back through the tracker.

A campaign's Fallback URL (and the workspace-wide fallback) accepts the same click macros as an offer URL, plus {campaign_name} and {_md5} — useful when the drop-off page needs to know which campaign sent the visitor.

Outgoing postback tokens

The outbound postback the tracker sends to a traffic source or on a campaign cycle supports everything in the offer macro table, plus the conversion-specific tokens below. These belong in a source's S2S postback URL, not in an offer URL.

TokenValue
{payout}The conversion payout being reported
{revenue} {profit}Revenue and profit for the row
{status} {status2}Primary status, and a secondary status when the row carries one
{_md5}MD5 hex of the click id
{unixconversiontime}Conversion time as Unix epoch seconds
event_1 … event_30Custom conversion event parameters

A literal payout=auto in a postback URL is replaced with the payout actually being fired, so one template can serve offers with different payouts. Unknown tokens in a postback URL stay literal; a known token with no value resolves to empty.

Geo, device and UTM values

Geo and device macros are filled from what the tracking request resolves — the visitor's IP, User-Agent and any proxy/CDN geo header — so they are available even when the source sends nothing. UTM macros come from the UTM parameters on the hit. Where a value could not be resolved, the macro is simply empty rather than guessed; that is the honest result, but it also means a report grouped by {city} will be sparse if your source never passes usable location data.

Keep the id in one place

The tracker appends click_id=… to every offer URL on its own, so the network parameter you add (for example &sub1={click_id}) is the only extra one it needs. Give the same parameter name to the network's postback template so what goes out comes back.
