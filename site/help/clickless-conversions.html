Clickless conversions and manual import

Record conversions without a click id using a transaction id or unique sub-ids, and import a batch of conversions from a file.

Updated 5 October 2026

When a conversion has no click id

A clickless conversion is one that arrives without the click id the tracker generated. It happens more often than people expect: a call centre closes a sale hours later, a CRM batches approvals overnight, or a network's postback simply does not echo the value you sent. The tracker's rule is that a conversion is never dropped — it is matched to the best available evidence, and if none of it is decisive the row is still kept.

The matching ladder

Matching runs in order and stops at the first confident hit:

  1. Transaction id. A repeat transaction_id (or external_id) updates the same row, so a re-delivered sale counts once.
  2. Unique sub-ids. Sub-ids 1–5 are compared against real clicks inside the workspace attribution window (default 7 days). The match must be unique — exactly one click — otherwise the tracker refuses to guess.
  3. The visitor. The first-party visitor id (aaa_vid) is stitched to that visitor's latest click (last-click) or earliest click (first-click), according to Settings → Attribution, again inside the window.
  4. Unattributed. If nothing resolves, the row is written with click id none: visible in reports, still editable, and re-attributable later.

Uniqueness is the safeguard

A shared sub-id is not enough. If two clicks match the same sub-ids, the tracker will not merge two customers — the conversion stays unattributed until you attach it by hand. That is deliberate: a wrong match is worse than no match.

Offline / phone ingestion API

For CRMs, call centres and other server-side systems, post the conversion to the ingestion endpoint. It takes a workspace API token as a Bearer header (or an admin session) and accepts a JSON object or a form-encoded body:

POST /backend/api/reports/ingest
Authorization: Bearer <api-token>

{
  "click_id": "9f2c1a7e-…",
  "status": "sale",
  "payout": 42.5,
  "transaction_id": "CRM-10432",
  "currency": "EUR",
  "occurred_at": "2026-10-05T14:02:00Z",
  "sub_id_1": "campaign-a"
}

The fields it understands:

FieldNotes
click_idOptional if another key is supplied.
statusDefaults to sale when omitted; built-in or custom statuses accepted.
payoutPlain number; a non-numeric value is rejected.
transaction_id / external_idThe idempotency key — re-sending the same value updates the existing row.
currencyAccepted here; unlike /pb, which has no currency parameter.
occurred_atISO-8601 timestamp of the real conversion.
sub_id_1 … sub_id_10Match keys and reporting dimensions.
phone, noteStored on the conversion history.

A valid call answers with a JSON result such as {"result":"created","attributed":true,…} or {"result":"updated",…} for a repeat; a bad payload gets a clear rejected reason rather than an error page. The endpoint matches click id, external id or transaction id first, then falls back to unique sub-ids inside the attribution window, exactly like the postback path.

Importing a batch from a file

Reports → Conversions → Import conversions takes a CSV-style list, one conversion per line:

click_id,payout,transaction_id,status

An existing click id accumulates onto its row; an unknown id creates an unattributed row rather than being discarded. The importer also accepts optional occurred_at and currency columns, and the status may be any built-in or custom status.

Which path to use

SituationUse
Network reports a sale in real timeIts S2S postback to /pb — see the postback reference.
Call centre or CRM closes offline ordersPOST /backend/api/reports/ingest, from the system that owns the order.
A partner emails a spreadsheetThe Import conversions dialog in Reports → Conversions.
A thank-you page with no server callbackThe conversion pixel or JS snippet — see Conversion pixel and JS tracking.

Why the currency note matters

Inbound /pb deliberately has no currency parameter — a conversion's currency comes from the offer or the workspace. The ingestion API and the CSV importer, by contrast, do accept a currency, because an offline order knows the currency it was sold in. If you are moving data from a CRM and the total is coming out in the wrong unit, check that the currency was sent on the ingestion call rather than assumed from the offer.

Confirming and fixing the result

  • Reports → Conversions lists every row, attributed or not; filter or edit to attach an unattributed conversion to the right click.
  • Logs → Conversions shows the history and the source of each event.
  • Health centre and the reports you already watch will show an unattributed spike if a feed starts sending bad keys.

Send the strongest key you have

A transaction id resolves instantly and idempotently. Sub-ids and the visitor id are fallbacks, not substitutes — they can match several clicks and then be refused. When a CRM can send both a transaction id and a click id, send both.
