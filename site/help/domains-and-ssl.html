Domains and SSL

Point your own domain at campaigns and offers so links stay clean, with certificates handled for you.

Updated 5 October 2026

What a tracking domain does

A tracking domain is the address your campaign links, served landing pages and postback URL all answer on. When you build a campaign you choose which domain its link uses, and the link takes the form:

https://<domain>/<alias>

Add domains under Tools → Domains with Add domain. Each row stores the hostname, whether to Redirect to HTTPS, its 404 handling (Handle 404 errors serves the tracker's styled page; Error returns a bare response), an optional Default campaign for visitors who reach / with no alias, and an optional group name. Add only a hostname you control, because you are about to point its DNS here.

Add the DNS record

The Domains page shows this tracker's public IP in its banner. You have two equivalent ways to point a hostname at it:

RecordUse it forValue
AAn apex or bare domain, such as example.comThe server IP shown in the Domains banner
CNAMEA subdomain, such as track.example.comYour tracker host

Use one record per hostname — you do not need both. A CNAME has the advantage that the tracker host's address can change without you editing DNS again.

While DNS propagates

  1. Add the domain row first. It shows a pending status while it waits.
  2. Create the record at your DNS provider, using the value above.
  3. Allow time to propagate — usually minutes, but up to a day where a long TTL was cached. You can keep building campaigns and offers in the meantime; nothing is lost.
  4. Do not send live traffic to the domain yet. Until it resolves here and has a certificate, HTTPS will not work, so test on the tracker host or another live domain in the meantime.

Check DNS

Each row has a DNS check button. It looks the domain up and compares the answer with this server's address, then shows one of three states:

  • Points here — the domain resolves to this tracker; you can issue a certificate.
  • Resolves elsewhere — DNS answers, but not with this server. Usually a stale record, a proxy in front of it, or a record created at the wrong provider.
  • No DNS — nothing resolves yet. Propagation has not finished, or the record is missing.

The Check domains statuses button re-tests every domain over HTTP and updates the Status column.

Update SSL

Once DNS points here, use the row's Update SSL for 90 days action. The tracker confirms the domain over plain HTTP and issues the certificate automatically. This can take up to 10 minutes per domain, so keep the page open until it confirms. The SSL Status and SSL Expiry columns then show the state — a day count while it is valid, and warning, critical, expired or No cert when it is not. With Redirect to HTTPS on, plain-http requests for this domain are upgraded to https.

Wildcards and renewal

The certificate follows the domain row, so it covers the exact hostname you added. Add every hostname you actually serve — for example track.example.com and www.example.com — as its own row. One entry does not cover its subdomains, and a wildcard certificate is not part of this flow.

Certificates are valid for 90 days and renewal is not automatic on every setup. Watch the SSL Expiry column and re-run Update SSL before it lapses, or enable the renewal timer on the host so it renews for you. A lapsed certificate breaks the HTTPS redirect for that domain, and links and postbacks that expect HTTPS start failing.

Why hits land in the right workspace

A domain belongs to exactly one workspace. On every click and every /pb postback the tracker reads the hostname the request arrived on, resolves the workspace that owns it, and then matches the campaign alias or click id strictly inside that workspace. Aliases are unique per workspace rather than globally, so two workspaces can each run a campaign called promo without colliding, as long as they are served on different domains. A request on a host that no workspace owns is refused rather than guessed, so a conversion can never be credited to the wrong workspace's numbers.

This is also why the postback URL you give a network must use the same domain as the campaign link. Pointing it at a staging or old domain sends the call to a workspace you are not watching. See Postback not recorded.

The certificate challenge runs over HTTP first

A certificate can only be issued after the domain already routes here, because the check is fetched over plain HTTP. Confirm DNS and allow propagation before pressing Update SSL.

One domain, many campaigns

A single domain can serve any number of campaigns through their aliases and can carry a default campaign for bare / visits. Add a second domain when you want separate branding, or to keep an old link alive.
