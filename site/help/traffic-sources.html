Adding a traffic source

Add a traffic source, capture its click-id convention, and generate a tracking link with that source's real macros.

Updated 5 October 2026

What a traffic source is

A traffic source is the record of where your clicks come from. It holds the source's own click-id convention, the macros it understands, where conversion data should be sent back to it, and the expected traffic loss. A campaign always points at one source, and that source is what lets the tracker name the channel behind every click.

The catalog and "New from template"

Open Manage → Sources. The catalog ships around 187 presets, each with the source's real pass-through macros filled in. New from template opens the catalog; Add source opens a blank form.

In the catalog you can search sources, and filter to All or With API integrations. A preset carries capability badges for the automation it supports:

BadgeMeaning
costCost update supported.
pause_campaignCampaign pausing supported.
blacklistBlacklisting supported.
pause_creativeCreative pausing supported.

A preset with no badges is marked No API integration — it still tracks clicks, it just cannot be driven by the automation the badges describe. If your source is not in the list, use Add source and fill in the same fields by hand.

The fields

FieldWhat it does
Source nameThe label used everywhere the source appears — reports, filters, the campaign picker.
Traffic loss (%)The expected gap between the clicks the source reports and the visits tracked here, kept for reconciliation.
S2S postback URLWhere the tracker sends conversion data to the source (outbound — see below).
S2S postback statusesCheckboxes for sale, lead, rejected and upsale, choosing which statuses fire the outbound postback.
Conversion fanout controlsTwo switches that thin out what the source is told — see below.
Additional settingsFree-form key/value pairs for the source integration, such as API keys.
Settings mappingRows of Name / Parameter / Token mapping the source's macros to tracker parameters.

The S2S postback URL here is outbound

Read this one carefully, because the same phrase means the opposite thing in the two records. On a traffic source, the S2S postback URL is outbound: it is the URL on the source's side that the tracker calls when a conversion lands. The tracker fills the placeholders with real values, for example:

https://source.example.com/post?clickid={click_id}&payout={payout}&status={status}

The source's postback template is not your tracker's /pb endpoint. On an affiliate network, the S2S postback URL is the inbound template you hand to the network so it can call you — that is covered in Adding an affiliate network and the postback reference.

Do not paste your own postback URL here

If you paste https://YOUR-TRACKER-DOMAIN/pb… into a source's outbound field, the tracker will call itself on every conversion. Use the URL the source gave you for receiving postbacks.

S2S postback statuses

The four checkboxes decide which conversion statuses are worth telling the source about. Tick sale and lead for the common case; add rejected if the source wants to know about reversals, and upsale if it pays on them. A status left unticked simply does not fire an outbound postback.

Conversion fanout controls

  • Don't forward upsell conversions to this source — sale and lead forwards are unaffected, and campaign postbacks are unaffected. Use it when the source only wants the first conversion.
  • Forward only this share of conversions (%) — leave empty to forward every conversion. The same click id always gets the same decision, so a source sees a consistent sample rather than a random flicker.

Settings mapping

Each row maps one value. Name is the human label, Parameter is the tracker parameter it lands in, and Token is the source's macro that fills it. For example, the Cost row maps a token of {cost} to the cost parameter so per-click spend is captured; {campaign_id} maps to utm_campaign. Mapped values flow into reports, filters, macros and postbacks. This mapping is also how the source's click id is captured — for example a token such as clickid on the row whose Parameter is click_id.

Meta needs no click-id mapping

Meta's fbclid is captured automatically from the ad URL and stitched with the _fbc and _fbp cookies. You do not map it, and you do not need a token for it. To push conversions back to Meta, see Sending conversions to Meta (CAPI).

Confirming it works

  • Health centre shows the last successful postback per source, which tells you quickly whether an outbound destination has gone quiet.
  • Logs → Internal postbacks shows the outbound delivery attempts this tracker sent, with their outcome.
  • Reports breaks any metric down by traffic source once clicks are flowing.
