Offers and offer URLs

Build an offer URL, place macros where the network expects the click id, and manage payouts and currencies per offer.

Updated 5 October 2026

What an offer is

An offer is the final destination of a click — the network’s page the visitor is sent to. Open Manage → Offers → Add offer to create one. The wizard is a short form; this page walks every field, then explains the one thing most people get wrong: getting your click id onto the network’s URL.

Every field

FieldWhat it does
Offer nameLabel shown in lists, pickers and reports. Use the network’s offer id in the name so you can find it fast.
Target URLThe page the visitor lands on. Accepts macros; the network’s click-id parameter must be placed here (see below).
Affiliate networkThe network this offer belongs to, so its click-id convention and postback template are known.
CountriesISO-code targeting list — search by name or code. Leave empty for all countries.
PayoutThe value a conversion is worth, in this offer’s currency. Set 0 for a rev-share offer.
CurrencyThe currency the payout (and the postback’s amount) is recorded in.
StatusActive, paused or archived. Archiving is a soft delete — restore any time.
Daily conversions capStop serving the offer once this many conversions land in a day; traffic overflows to the Overflow offer.
Overflow offerWhere traffic goes when the daily cap is reached.

Below the main fields there are also Tags (free-form, e.g. nutra, tier1), Notes and an optional CAPI pixel binding. Offers can be created in bulk with a CSV whose header is id,name,url,affiliate_network_id,countries,payout,currency,status,tags,daily_conversions_cap,overflow_offer_id,notes.

Putting the network’s click id into the Target URL

When a click-out happens, the tracker substitutes every {macro} in the Target URL from the click’s data and also appends click_id=… automatically. That auto-append is not enough on its own: a network reads its own parameter name, and if that parameter is not on the URL the network has nothing to echo back on the postback. Your conversion arrives with an empty or wrong click id.

The fix is to insert the network’s parameter into the Target URL with the {click_id} macro. If the network expects sub1, the URL becomes:

https://network.example.com/click?offer=123&sub1={click_id}

Other networks use different names — s1={click_id}, aff_sub={click_id}, and so on. Use whichever the network documents. One caution: the “Offer parameters” field on the network record is a stored reference only. It is not appended to the offer URL at runtime, so the parameter has to live on the Target URL itself.

Offer URL macros

Placeholders are single-brace; unknown macros are left untouched. The ones you will reach for most:

MacroValueMacroValue
{click_id}Unique click id{visitor_id}First-party visitor id
{sub_id_1}…{sub_id_10}Sub ids 1–10{offer_id} / {campaign_id}Offer / campaign id
{country} / {city} / {region}Geo{os} / {browser} / {device_type}Device & platform
{language}Locale{referrer} / {keyword}Context
{cost} / {currency}Click cost & currency{ip} / {isp}Network details
{utm_*}UTM tags{_md5} / {payout}Hashed value / payout

The full set also includes {device_brand}, {os_version}, {browser_version}, {connection_type} and {landing_id}. Local landing files use {offer} for the click-out URL. See Click IDs and URL macros for how the id travels end to end.

Rev-share offers

With a rev-share deal the amount you are paid is a share of the sale, so it cannot be known when you build the offer. Set Payout to 0 and let the value come in on the postback’s payout (or amount/sum) field. The tracker accumulates that amount onto the conversion, and repeats for the same click add up — that is how lifetime value builds. Set the Currency to match what the network pays, because the postback itself carries no currency parameter.

Daily caps and overflow

Daily conversions cap counts conversions per day for the offer. Once it is reached the offer stops taking new traffic, and any click that would have gone to it is sent to the Overflow offer instead. Set the cap as a whole number; leave it empty or 0 for unlimited. If the cap is hit and no overflow offer is configured, the offers flow simply stops matching and normal campaign fallback applies.

The one that breaks postbacks

Never assume the auto-appended click_id=… is enough. Check the offer’s Target URL carries the network’s own parameter with the {click_id} macro — for example &sub1={click_id}. Without it, conversions land unattributed and look like they were never tracked.
