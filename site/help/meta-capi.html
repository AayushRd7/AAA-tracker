Sending conversions to Meta (CAPI)

Send conversions to Meta server-side from Manage → CAPI integrations, with the statuses to send, a default currency and a dry-run.

Updated 5 October 2026

What the conversion API does

The Meta Conversions API (CAPI) sends your conversions from the tracker's server straight to Meta, independent of the browser — so they survive ad blockers, browser restrictions and the drop in third-party cookies. Meta matches each event back to the ad click using the click identifiers the tracker captured (see below), not the tracker's own click id: a click that arrived with fbclid= is what makes a match possible.

Everything lives on Manage → CAPI integrations — open the Meta tile and press Manage all to see its pixels. Meta is the only platform whose sender is live today; the other tiles store records but send nothing yet.

Turning it on

  1. On Manage → CAPI integrations, open the Meta tile.
  2. Switch on Send conversions to Meta.
  3. Set the dataset and token — either the fallback fields or one or more pixel records (below).
  4. Leave Dry-run on and use Send test event while testing, then clear the test event code and turn dry-run off.
  5. Press Save settings — it stays disabled until the stored settings load, so a failed load cannot overwrite your configuration with the page defaults.

Fallback dataset versus pixel records

There are two ways to tell the tracker where to send:

WhereFieldsWhen it is used
Fallback (on the Meta panel)Fallback Dataset / Pixel ID and Fallback access tokenOnly when no pixel is bound. The token is stored as a secret.
Pixel records (Add new pixel)Pixel / Dataset ID, API key / Access token, plus the per-pixel options belowWhen bound to a traffic channel or an offer. A pixel's own id and token win.

Bind a pixel in one place: at the traffic-channel level to send only that channel's conversions, or at the offer / website level to send all of that offer's conversions from any channel. If it is bound at both levels, the sender resolves the channel first and still sends once, so this is redundant rather than harmful.

The access token and the test event code

The access token authenticates the call. Treat it as a secret: masked and stored hidden, and it must belong to the same dataset as the id beside it. A mismatched pair fails at Meta and appears in Logs → Internal postbacks as a failed send with Meta's error text.

Test event code is optional. With it filled in, every event is routed to the Test Events tab of Meta's Events Manager instead of the normal stream — useful for confirming the wiring, but those events do not count as conversions in ad reporting. Clear it when you go live.

Which conversion statuses to send

The Send these conversion statuses checkboxes control what leaves the tracker. Defaults are lead, sale and upsale; custom statuses you defined also appear. A status that is not ticked is skipped silently — no event, and no row in the outbound log.

Each status maps to a Meta event name: defaults are sale → Purchase, lead → Lead and upsale → Subscribe. With a pixel record, the pixel's Default event name applies to every status unless a Custom conversion matching row overrides it.

Currency and value

The event's value is the conversion payout; its currency is the conversion's own, falling back to the panel's Default currency (USD, EUR, GBP or JPY). A pixel can carry payout customisations — one row per conversion type with a fixed Value and/or Currency that overrides those defaults. Leave both empty to keep the conversion's numbers.

fbclid, _fbc and _fbp are captured for you

You do not map Meta's click identifiers. On a Meta ad click the tracker reads fbclid from the ad URL automatically and stitches it with the _fbc and _fbp cookies:

  • fbp comes from the _fbp cookie.
  • fbc uses the _fbc cookie when present; otherwise it is derived from fbclid in Meta's required form fb.1.<unix-ms>.<fbclid>.

Those values are stored on the click and carried into the event's user_data, along with the visitor's IP and user agent. With Include hashed email/phone when the postback provides them on, any email or phone on the conversion is normalised and SHA-256 hashed before sending. If a redirect, landing page or URL builder strips the query string, the click arrives without fbclid and Meta has little to match on — check that first when conversions do not appear.

Per-pixel overrides

A pixel record can be tuned beyond its id and token:

FieldWhat it does
Default event nameThe Meta event used for every conversion this pixel receives unless a custom match overrides it.
Event URLOptional event_source_url sent with the event.
Action sourceStore tracking URL, App, Offline, Chat or Other.
Data Quality API TokenOptional; stored as a secret.
Statusactive or inactive.
Custom conversion matchingMaps a conversion type to a specific Meta event name; anything not listed uses the default event name.

Dry-run and Send test event

Dry-run (build + log the payload, send nothing) is on by default: the payload is built and the outcome recorded, but no HTTP call is made. Send test event saves the settings, then sends one synthetic event so you can confirm credentials and formatting; the result is shown on the page. Turn dry-run off only when you are ready for real events to reach Meta.

The two silent failures

Dry-run left on, and a status that is not ticked. Both write no row to Logs → Internal postbacks, so the sender looks broken when it is simply not running. Confirm those two first, then follow Meta shows no conversions in order.
