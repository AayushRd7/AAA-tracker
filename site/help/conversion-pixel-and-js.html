Conversion pixel and JS tracking

Client-side conversion tracking with the pixel and JavaScript snippet, and when to prefer server-to-server instead.

Updated 5 October 2026

Server callback or browser callback

Most conversion data should arrive server to server: the network or your CRM calls the tracker directly, which does not depend on the visitor's browser and cannot be blocked by it. There are two cases, though, where no server callback exists — a thank-you page on a destination you do not control, or a client-side event such as a form submit — and that is what the conversion pixel and the JavaScript snippet are for. This page covers both, and the postback reference covers the server path.

Direct JS tracking

Add the snippet to any page on your own site:

<script src="/t.js?c={alias}"></script>

The script keeps a first-party visitor id in the aaa_cid cookie (with a localStorage copy, 30 days), then posts a visit to /t/collect using sendBeacon, falling back to fetch and finally an image request. The visit is recorded as a visit, not a click, and the response is {"status":"ok","click_id":"…"}. Once the script is loaded it exposes three functions:

FunctionWhat it does
aaaTrack()Returns the visitor's click id (and fires the collect).
aaaClickThrough(url)Appends &click_id= to a click-out URL so /c/{alias}/{offer} reuses the same id.
aaaFire(status, payout, extra)Fires a client-side conversion pixel for this visitor.

/t/collect also works on its own as a GET or POST with ?c={alias}&click_id=…. It collects UTM parameters and the page title, honours bot rules (blocked bots get a 404) and respects the GDPR opt-out cookie.

The conversion pixel

The pixel is a single request that records a conversion and returns a 1×1 GIF:

GET /p/{alias}?click_id=9f2c1a7e&status=sale&payout=10.5

The click id comes from ?click_id= or, when the snippet is present, from the aaa_cid cookie it set. Extra attribution fields — transaction_id, external_id and sub_id_1 through sub_id_10 — pass through as query parameters. A bare pixel with no click id and no attribution parameters gets a 400, and an opted-out visitor gets the GIF with nothing recorded. Because it is addressed by campaign alias, the pixel is bound to one campaign.

How the click id is carried through

  1. The visit lands and /t.js writes the visitor's click id to the aaa_cid cookie.
  2. aaaClickThrough(url) appends click_id=… to the click-out so the offer click reuses the same id rather than minting a new one.
  3. On the thank-you page the pixel reads ?click_id=… first and falls back to the cookie, so you get the same id without wiring anything.

If you do not use the snippet, pass the click id to the pixel yourself in the URL. If neither the URL nor the cookie has an id, supply a transaction id or sub-id and the pixel takes the clickless path.

Pixel or snippet?

SituationUse
A thank-you page you host, no server callbackThe pixel with ?click_id=…, or aaaFire() if the snippet is already on the page.
You want every page view tracked, plus a conversion laterThe JS snippet — it sets the cookie and exposes the API.
A destination page you do not controlThe pixel: paste one <img> tag with its click id hard-coded, or render the URL server-side.
The conversion happens on a server you ownPrefer S2S — see postbacks and offline ingestion.

JSON-mode pixel

Add &fmt=json to get a JSON response instead of a GIF:

curl "https://your-domain.com/p/my-campaign?click_id=9f2c1a7e&status=lead&payout=3.25&fmt=json"

This is the right form when the call is made by script or by a server rather than by a browser image tag, because you can read the result — for example to confirm the conversion was recorded or to surface an invalid status. The GIF form is for embedding on a page, where nothing reads the response.

Cross-domain and impressions

The pixel and /t.js are served with open CORS headers so they work from any domain, which is what lets you track a destination page you do not host. There is also an impression pixel, GET /i/{alias}, which records an impression and returns a 1×1 GIF so view-through reporting can attribute a later conversion through the same aaa_cid cookie.

Testing a pixel by hand

There is no test button. Fire a click on the campaign link, copy the click id from Logs → Clicks, then call /p (or /pb) with curl and &fmt=json. Confirm the conversion in Reports → Conversions. That exercises the same path the browser would.

Browser tracking can be blocked

Ad blockers, ITP and disabled cookies can stop a pixel or script from firing. Treat browser tracking as a convenience for pages with no server callback; treat the server-to-server postback or the ingestion API as the dependable path for money-critical conversions.
