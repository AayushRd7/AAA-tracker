Landers and the landing editor

Upload landers, edit them in the landing editor, and route visitors between a landing page and an offer inside a flow.

Updated 5 October 2026

What a lander is

A lander (landing page) is an optional page that warms the visitor up before the offer. In a flow it sits between the incoming click and the click-out: the tracker serves your page, and a link on it sends the visitor on to the offer. Two flow schemas use landers — landing_offer serves a landing and then the offer, and landing_only serves the landing with no click-out. The multi schema can rotate one landing and one offer from pools. The Campaigns and flows page covers how a flow picks among them.

Local vs external landers

Every lander has a type. The difference is where the page actually comes from:

TypeBehaviour
file (local file)An uploaded archive or single file, served from the tracker. This is the only type you can edit in the landing editor.
linkRedirects the visitor to an external landing URL. Nothing is hosted here.
mirrorFetches an external URL server-side and re-serves it through the tracker.

Use local when you want to host and edit the page, rewrite its assets and route its click-out through the tracker. Use link or mirror when the page already lives elsewhere and you only want to point at it.

Uploading a lander

Open Manage → Landers and press Create landing. On the Upload file tab, fill in the fields and attach the file:

  • Folder name — lowercase letters, numbers and underscores only, up to 250 characters. The local lander is served at /l/<folder>.
  • Name and Tags — the internal label and free-form tags for filtering.
  • Landing type — choose file.
  • Landing file (.zip, .php, .html) — the upload itself.

A .zip must contain an index.php or index.html at its root (not nested inside a subfolder). You can also upload a single .php or .html file.

Grab from URL instead

The Grab from URL tab fetches a page server-side and stores it as a local lander. A built-in guard accepts only http(s) URLs with publicly resolvable hosts and refuses localhost and internal addresses; tick Allow internal/private address (own infrastructure) only when grabbing from your own infrastructure behind the same proxy. A grabbed page is capped at 3 MB.

Allowed file types and size caps

LimitValue
Upload file types.zip, .php, .html
Files the editor accepts.html, .php, .css, .js, .jpg, .jpeg, .png
Zip entriesUp to 2000 files
Single file inside a zipUp to 50 MB
Total uncompressed archiveUp to 200 MB, and no more than a 100:1 compression ratio
Grabbed pageUp to 3 MB

The archive caps are checked before extraction, so an oversized or zip-bomb archive is refused rather than expanded.

The landing editor

Local landers can be edited in the built-in code editor. In the Landers list, open a row's Code editor action — it opens /backend/editor?landing={id} for that lander. The page has two panes:

  1. File tree (left). Every file and folder in the lander, so you can see the whole structure at a glance. Click a file to open it. Create file adds a new one by path (for example subdir/newfile.php); Upload file drops an additional asset into the lander.
  2. Editor (right). Syntax-highlighted editing for HTML, CSS, JS and PHP. An Unsaved changes marker appears once you edit; Save writes the file back. Insert script splices a saved script from your library at the cursor or before </head> / </body>.

The {offer} click-out macro

Inside a local lander's HTML, the placeholder {offer} is replaced at serve time with the click-out URL /c/{alias}/{offer_id}. That URL carries the landing id, the click id and the mapped passthrough tokens automatically, so the tracker can attribute the click-out and then redirect to the offer. A button therefore looks like this:

<a href="{offer}">Continue</a>

Leave {offer} intact — if you replace it with a hard-coded destination, the click-out no longer passes through the tracker and the step loses its attribution. The offer's own URL is where the other macros ({click_id}, {sub_id_1}, …) are placed; see Offers and offer URLs and Click IDs and URL macros.

How a flow points at a lander, then an offer

  1. In the campaign wizard, give the flow a schema that uses landers — landing_offer to serve a page then the offer, or landing_only to serve the page alone.
  2. Attach the lander (or a pool of them under multi).
  3. Attach the offer. The visitor loads the lander, and clicking its {offer} link hits /c/{alias}/{offer_id}, which redirects to the offer URL.

Lander and offer are chosen per visitor, and with binding on a visitor keeps the same variant on return.

The click-out that does not convert

If click-outs show no conversions, check that the button still uses {offer} and that the archive had its index.html or index.php at the root. A hard-coded link skips the tracker; a nested index means the lander has no entry page to serve.
